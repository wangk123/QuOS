# QuOS 项目约定

## 产品定位

质量工作台(当前单人使用,架构不设单人限制)。平台只做三件事:

1. **给 agent 定标准**——统一接口 + 规则校验,不合格的产出拒收;
2. **给人做闸门**——评审交互(最小决策单元答题、定稿拍板、抽查);
3. **给文档管生命周期**——版本快照 + 变更记录 + 回滚。

AI 加工完全外部化:外部 agent 结合项目内 skill(`.agents/skills/`)执行需求整理等加工,通过平台接口提交结果。平台不内置任何 LLM 调用。触发权在 agent 侧(用户在 agent 会话中发起),平台保持被动服务;平台侧触发 agent 属远期演进。

## 技术选型

- 后端:Python 3.12+ / FastAPI / SQLModel / SQLite(唯一真相源,单文件库)
- 前端:Vite(沿用既有前端栈重写页面)
- 包管理:uv;本地运行,localhost,接口无鉴权
- 原始材料文件(pdf/图片等二进制)存文件系统,库内存路径 + hash;解析文本入库(出处核对需在文本内定位)

## 全局约束

- 文档版本平台自管(定稿快照 + 条款级变更记录),不依赖 git 管理文档
- 接口校验两级:硬错误拒收(出处定位不到、编号重复等),软警告转题目进人闸门
- 管线状态全部归平台;agent 无状态、短事务(唤起 → 拉取 → 加工 → 提交 → 退出)
- 规则编号全局稳定、作废留痕(R12 由 R15 替代式引用合法)
- 题目四种题型:选择题 / 确认题 / 填空题 / 批量扫
- 主产物为章节式需求文档(给人读),规则条目库为锚点层(给机器引用)
- v1(`server/app` 的 LLM 编排与树/证据/规则存储)整体废弃,旧数据不迁移
