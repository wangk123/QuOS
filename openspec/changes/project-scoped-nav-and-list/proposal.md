# 项目资源导航与列表优化（含状态两轴）

## Why

- 左侧导航树把所有项目当一级菜单平铺直切，与平台 IA 相悖：材料/文档/版本是**项目内资源**，未来还有案例管理、接口自动化等更多项目内模块。项目是容器，切换应发生在项目列表，进入项目后才呈现资源导航。
- 项目列表信息混杂：项目级信息与需求文档（项目内资源）的版本/状态混在一张表上——**项目是项目，需求是需求，两层概念不得混用**。
- 项目自身缺治理属性：无状态（进行中/暂停/结项）、无版本；项目名称可重复；定稿版本号无格式约束（存量 `v2-onepager`）。

## What Changes

- **侧栏仅项目内**：项目列表页无侧栏（全宽，顶栏显示品牌）；进入项目后侧栏=资源导航（返回入口+项目名+需求管理组+六个未来模块灰色占位「即将上线」）。子页（材料/评审/版本）布局交互不动。
- **状态两轴正交**（设计基准：状态设计 v1，2026-10-21 用户定稿）：
  - **项目状态=能不能写**：人手动设的治理开关，三态——进行中（默认，写权限全开）/ 已暂停（临时冻结，只读可恢复）/ 已结项（交付退役，只读可重开）。只读态拦截全部写操作。
  - **需求状态=等谁**：平台按事实派生，五态——未开始 / 待评审（人作答）/ 待重交（agent 取答案重交）/ 待定稿（人抽查定稿）/ 已定稿（无人，等新素材）。**不出现在项目列表**，只在项目内露出（评审页工具条、版本页草案条目文案升级）。
- **项目列表**：列=项目（名称+描述）/ 材料 / 批注 / **项目版本** / **项目状态** / 操作。项目版本=项目自有属性（手动维护，x.x.x 硬校验，默认 1.0.0）；操作栏统一同族文字按钮（进入/编辑/删除），编辑弹窗含状态切换。
- **项目名称全局唯一**：创建与改名重名拦截（前端内联提示+后端 409）。
- **定稿版本号 x.x.x**：finalize 硬校验（422），建议值按基线 patch 递增；存量版本号不迁移。
