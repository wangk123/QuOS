# Design: doc-reading-experience(v2 重构版)

> 设计基线:main@f14ac42(已 merge 入 proto/doc-visual-r1)。实证:多模态 draft 43(48 章/123 规则/75 para/0 exceptions/0 states)、云风控 draft 51、`md_import.py`、`models.py`、DocPaper.vue。
> 标注约定:「**取舍**」= 设计者替用户做的判断,评审可推翻;推翻只影响对应小节。
> 阶段序:**A 章节架构 → B 章内编排 → C 导入归一与校验 → D 阅读呈现**。A/B 是生成侧纪律(改 skill),C 是平台侧兜底与历史修复,D 是原渲染方案精简保留。A/B/C 解决「内容没质量」,D 解决「质量好但读不快」。

## 0. 病灶实证(方案针对的事实)

| # | 病灶 | 实证 | 根因环节 |
|---|---|---|---|
| 1 | 壳章堆叠 | 多模态:「需求主体」壳章下挂 10 个功能域子章,123 规则绝大多数在其下;云风控单域一章无此问题 | req-organize 骨架固定八层,无规模判据 |
| 2 | 骨架标签字面进正文 | 每章开头固定【为什么存在】【叙述】【规则】【异常路径】四个标签 para(draft 43「受理与文档接入」等全量如此) | skill「章内顺序指引」被字面执行;md_import 照单全收 |
| 3 | 结构化块形同虚设 | 全文 0 states / 0 exceptions;异常条目「Profile 非 READY → 显式失败」散落 para | 生成侧不选形态;导入侧不转换;评审无此项;平台无告警 |
| 4 | 大章规则堆叠 | 「受理与文档接入」12 条规则 + 4 个 para 挤一章,无分组叙事 | skill 无规则分组指引 |

对照:云风控(小需求)单章收纳合理——**问题是规模判据缺失,不是单章本身有错**。

## A. 章节架构弹性(消除壳章堆叠)

### A.1 skill 纪律(req-organize)
骨架从「固定八层」改为「**头尾固定 + 中段弹性**」:

- **头**(恒定):文档头 → 背景与目标 → 用户与场景 → 系统总览。
- **中段**(按规模伸缩,判据可判定):
  - 功能域 **≥3 个** 或全文规则 **>30 条** → 每个功能域直接作为顶层章(章号接在总览之后);域内再按内容分子章(如对外 API 交付 → 接入与受理/查询接口/幂等)。
  - 否则(1-2 个域)→ 允许单章「功能需求」收纳,域作小节。
- **尾**(恒定):全局业务原则(GP)→ 非功能需求 → 约束假设与开放问题 → 术语表与变更记录。
- 「需求主体」壳章废除:不再作为标题出现,GP 独立成章紧邻总览(多模态现状已是如此)。

**取舍**:判据阈值(≥3 域 / >30 规则)取保守值,宁可早拆不晚拆;两判据满足其一即拆。

### A.2 平台归一(md_import,对历史与违约产物兜底)
导入转换时执行**壳章提升**:
- 字面匹配:标题为「需求主体」且自身无正文块无规则 → 子章整体上移至壳章原位,壳章删除。
- 结构兜底:自身无块无规则、子章 ≥3 个、且**子树(含孙章递归)**承载规则合计 ≥ 全文 50% 的任意壳章 → 同上提升。
- **取舍**:头部三容器(背景与目标/用户与场景/系统总览)**不提升**——它们是文档逻辑分区,目录分组有意义;只有承载功能内容的「需求主体型」壳才拆。存量草案零迁移,重导后自然获得新架构。

## B. 章内编排去模板化

### B.1 章首自然开头(消除标签)
- skill:「为什么存在+叙述」合并为**章首一段自然话**:这章讲什么故事、服务哪个用户类的哪个场景、梗概一句。禁止任何【标签】字面;「规则」「异常路径」不再作为正文标签出现(规则由规则行承载,异常由块承载)。
- md_import 剥离与合并:连续的【为什么存在】para + 【叙述】para → 剥标签合并为一个 para;孤立的【规则】【异常路径】【背景】标签 para → 剥标签,空壳删除。

### B.2 先选形态,后写文字(结构化块硬纪律)
- skill 把现有「结构化内容用块」从建议升级为**章级判据**:
  - 异常/失败/拒绝路径内容 → **必须** exceptions 块(每条「触发 → 行为」);
  - 状态流转 → **必须** states 块;
  - 参数/枚举/清单 ≥3 行 → **必须** table 块;
  - 链路 → figure(线性链)或 diagram(mermaid);
  - 叙述性内容才允许 para,单章纯 para 不超过「开头一段 + 少量衔接」。
- **取舍**:不设「每章必须有图」类反模板指标——形态跟内容,没有异常内容的章不造 exceptions。

### B.3 大章规则分组
- skill:章规则 >8 条时按子主题分组叙事(域码或小标题),禁止 12 条规则裸排;分组是叙述组织,不强制建子章。

## C. 导入归一与平台校验

### C.1 md_import 三项归一(A.2 壳章提升、B.1 标签剥离合并,加:)
- **异常条目成块**:【异常路径】标签后连续的 `- ` 列表条目或「含 → 的单句 para」收集为 exceptions 块 items,直到下一个非条目内容。
- 归一动作记入导入报告(detail 列明:壳章提升 ×N、标签剥离 ×N、异常成块 ×N),重导效果可核对。

### C.2 兜底(一段话,不展开)
生成侧纪律管不住时,平台软告警兜底:骨架标签字面残留、全 para 大章、壳章结构——软警告转题进人闸门,不阻塞。req-review 增 S 结构组(壳章/章首标签/成块/分组四个检查项)。细节口径实施时定,不在此预设。

## D. 阅读呈现(原方案精简保留,内容质量落地后的配套)

- **D1 渲染强化(零契约)**:章级主题色 10 色循环+编号徽章、章末规则速览 chips、文档头统计(前端派生)、目录滚动联动。
- **D2 行内强调**:para 与规则 text 支持成对 `**`;md 导入保留标记(标题/表格/flows/violation 等其余字段剥星号);前端 esc→白名单渲染章色;锚定与术语搜索在剥标记纯文本上执行,不允许静默丢锚;不成对 `**` 按格式契约拒收;密度过高的强调转人裁。
- **D3 结构增量**:meta 可选 summary/keywords/reader_paths、cards 块(知识卡片)、文末「待确认问题」汇总区(=pending agent 批注只读聚合,pending 清零自动消失)。md 导入不转换 D3 新字段(agent 走 payload 路径)。
- 与 A/B/C 的关系:A→B→C→D 顺序;A/B 改 skill 后新生成文档即带新结构,C 修复历史,D 让好结构读得快。

## E. 困难应对对照(更新)

| 前期识别的困难 | 本设计解法 |
|---|---|
| 章节堆一块(用户主诉) | A 规模判据+壳章提升 |
| 章内硬模板(用户主诉) | B 章首合并+形态硬纪律+标签剥离 |
| AI 结构质量漂移 | skill 判据 + C 兜底告警 + 评审 S 组 |
| 批注锚点漂移(D2) | 匹配剥标记;A/C 改章节层级与块归属,规则行文本不变,锚定输入稳定 |
| 存量文档 | 零迁移;重导经 C 归一;D 缺省降级 |
| 工程协调 | 基于 merge 后 main;分支 proto/doc-visual-r1 |

## F. 目标画面(方案要抵达的读者体验)

多模态文档重导后:目录里 10 个功能域平铺顶层,拿目录问一个用户方读者,他 **10 秒内**能找到自己关心的功能域;点进任一章,第一段就是一段说人话的故事开头(没有【为什么存在】标签),异常路径是醒目的异常块而非散落正文,12 条规则的章有分组叙事而不是裸排。云风控(小需求)重导后:单章结构不变——规模判据保护了小文档不被过度拆分。

实施顺序:A(skill)→B(skill)→C(平台归一)→D1/D2/D3(呈现),每阶段独立提交。实施计划在本设计评审通过后产出。
