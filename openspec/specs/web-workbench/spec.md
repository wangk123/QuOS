## Requirements

### Requirement: 平台骨架与项目内导航
前端 SHALL 采用深色侧栏 + 浅色内容区的平台骨架,**侧栏仅在进入项目后呈现**:
- **平台级(项目列表态)无侧栏**:内容区全宽,顶栏左侧显示 QuOS 品牌标记与「项目总览」;项目不在导航中平铺直切;
- **项目内(进入项目后)**:侧栏为项目内资源导航——「返回项目列表」入口、当前项目名、「需求管理」模块组(材料 / 文档评审 / 版本,材料与文档评审带数量徽标)与未来模块(案例管理 / 接口自动化 / UI 自动化 / 性能测试 / 安全测试 / 环境管理)灰色占位项(标注「即将上线」,不可点击)。

项目切换只经项目列表的「进入」操作完成;材料、评审、文档是项目内部资源,不作为全局一级页面;面包屑项目内为 QuOS / 项目名 / 子页,列表态为 QuOS / 项目总览。
#### Scenario: 进入项目
- **WHEN** 用户在项目总览点击某项目的「进入」
- **THEN** 进入该项目的文档评审页,出现项目内资源导航侧栏(返回入口 + 项目名 + 需求管理组),文档评审入口带待处理批注数徽标
#### Scenario: 项目列表态无侧栏
- **WHEN** 用户位于项目总览
- **THEN** 页面无侧栏,内容区全宽,顶栏左侧显示 QuOS 品牌;不出现任何项目或项目内资源入口
#### Scenario: 未来模块占位
- **WHEN** 用户处于项目内查看侧栏
- **THEN** 案例管理、接口自动化、UI 自动化、性能测试、安全测试、环境管理以灰色禁用样式呈现并标注「即将上线」,点击无响应

### Requirement: 文档评审页布局
文档评审页 SHALL 为固定视口结构(各栏独立滚动,页面不整体滚动):文档区 = 文档正文(章节层级编号渲染,正文块按 para/states/table/figure/exceptions/diagram 分派——diagram 块以 sandbox iframe srcdoc 渲染自包含 HTML 图(禁脚本执行,高度自适应),figure 块以流程条呈现线性链路,存量 mermaid 块降级显示源码并附重画提示;规则编号锚点,恒全宽) + 内嵌目录列(章节树:层级编号+每章批注计数;三态 pinned 常驻挤占正文 / hover 悬浮浮层 / hidden 只留把手;右缘拖拽调宽限界并记忆);术语表以文档末章词条表呈现(术语/释义/出现章节,chip 点击定位);右 = 批注栏。工具条含:草案状态徽标、基于基线版本与摘要文字、**定稿发版按钮**。
#### Scenario: 独立滚动
- **WHEN** 用户滚动文档正文
- **THEN** 仅文档区滚动,批注栏位置不动
#### Scenario: 目录宽度拖拽
- **WHEN** 用户拖动目录右缘把手调整宽度
- **THEN** 目录宽度在限界内变化并记忆,刷新后保持;正文流式区域相应伸缩
#### Scenario: diagram 块 sandbox 渲染
- **WHEN** 文档正文渲染 diagram 块(自包含 HTML 图源)
- **THEN** 图以 sandbox iframe(无 allow-scripts)内联呈现,高度按内容自适应,暖纸面底色随图自带,不注入平台主题
#### Scenario: 存量 mermaid 图降级提示
- **WHEN** 文档正文渲染 text 非 HTML 形态的 diagram 块(存量 mermaid 源码)
- **THEN** 降级显示源码并提示「存量 mermaid 图,待迭代重画为 diagram-design」,不报错不空白

### Requirement: 正文批注与规则锚点
文档正文 SHALL 支持批注高亮标记(未答琥珀、已答绿)与规则编号锚点:点正文标记激活右栏对应批注卡;点规则编号弹出 popover(怎样算违反/出处引用/材料 hash)。
#### Scenario: 点规则编号
- **WHEN** 用户点击规则编号 R13
- **THEN** 弹出 popover 展示可判定表述与出处引用,点击外部关闭

### Requirement: 版本页
版本页 SHALL 呈现版本时间线(草案评审中项 + 历史定稿项)+ 选中版本的条款级变更 diff;每个已定稿版本提供「回退到此版」操作;发版后新版本带发版说明出现在时间线顶部。
#### Scenario: 回退基线
- **WHEN** 用户在 v2 上点击「回退到此版」并确认
- **THEN** 当前基线置为 v2,v2 之后版本保留在历史中,后续草案基于 v2 加工

### Requirement: 项目列表页
项目总览 SHALL 以表格呈现全部项目,列固定为:项目(名称+描述)、材料数、待答批注数、**项目版本**(项目自有属性,x.x.x)、**项目状态**(进行中/已暂停/已结项)、操作;需求文档的版本与状态不出现在列表。操作栏使用同族文字小按钮:进入(主色)、编辑、删除(危险色,删除保留二次确认弹窗),不混排图标按钮。新建/编辑弹窗含状态字段(下拉三值,按合法转移呈现可选项)与版本字段,重名即时报错。
#### Scenario: 操作栏风格统一
- **WHEN** 用户查看项目列表操作栏
- **THEN** 进入/编辑/删除为同一尺寸与形状的文字按钮,仅以颜色区分语义
#### Scenario: 重名拦截提示
- **WHEN** 用户新建或改名时输入与现有项目重复的名称并提交
- **THEN** 表单在名称字段内联提示「项目名称已存在」,不创建/不保存
#### Scenario: 列表切换项目状态
- **WHEN** 用户在编辑弹窗将进行中项目设为已暂停并保存
- **THEN** 列表该项目状态列显示「已暂停」(琥珀),后续写操作被平台拒收并 toast 提示

### Requirement: 需求状态徽标
评审页工具条的状态徽标与版本页时间线的草案条目徽标 SHALL 显示后端派生的需求状态(未开始/待评审/待重交/待定稿/已定稿)文案与对应色(待评审=琥珀、待重交=蓝、待定稿=琥珀、已定稿=绿);此为既有徽标位的文案级升级,布局与交互不变。
#### Scenario: 评审页徽标随作答流转
- **WHEN** 用户答完评审中草案的最后一条 pending 批注
- **THEN** 评审页工具条徽标由「待评审」变为「待重交」
