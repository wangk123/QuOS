# 需求一页纸（req-onepager）

把一份成稿需求文档提炼成一页纸，让评审人在读正文前 2~3 分钟建立**需求画像**：这是什么、解决什么、给谁用、怎么工作、由哪几块能力组成、边界在哪、要裁多少题。

**一页纸是画像，不是章节概要拼盘。** 逐章摘要的堆砌读完串不成整体——看完一张张「这章有什么」，脑子里立不起「这个需求主要是做什么」。成败判据只有一个：**只看一页纸的人，能否正确复述这个需求的样子**。

本 skill 是独立轻量步骤：输入一份成稿（过完 req-review 门的 md），输出一页纸 md，**一次提炼完成**——不做评审、不做修复循环、不做多轮编排。

## 输入与输出

- 输入：成稿需求文档（markdown）。
- 输出：`{文档名}-onepager.md`，骨架固定如下（平台按此骨架渲染，语法必须逐条遵守）。

## 固定骨架（输出格式，逐字遵守）

```markdown
# {系统名} · 需求一页纸

> {版本} · {日期} · 待裁 {K} 题

**这是什么**：{一句话定位：给谁、做什么、机器与人怎么分工}
**解决什么**：{痛点 → 价值，一句}
**给谁用**：{用户类列表}
**不做什么**：{2~4 条边界}

## 核心链路
{材料进入 → 解析识别 → 人工确认〔人工〕 → … → 交付}

{可选 1 行链路注解}

## 能力速览

### 主线 · {副题}
**{能力名}**（{角色}）〔正文 {N 或 N-M}〕：{2~3 句精炼叙述，高亮词 **粗体**}

### 支撑 · {副题}
**{能力名}**（{角色}）〔正文 {N 或 N-M}〕：{同上}

## 场景速览
{M 个场景名，用「、」分隔，一行}

## 待裁事项
送裁 {X} · 确认 {Y} · 填空 {Z}——评审前先看文档末问题清单
```

语法细节：

- 核心链路：节点以 `→` 连接一行；**人工环节节点尾缀 `〔人工〕`**；
- 能力卡：每卡一个段落，`**能力名**（角色）〔正文 章号〕：叙述`——全角括号与〔〕逐字如此；合并卡章号给范围（如 `5-6`）；**（角色）= 该能力在整条链路中的角色词，2~5 字**（如「业务载体」「入口标准化」「定类」「核心产出」「质量闸」「调优面」「配置底座」），**是角色不是用户类**——不要填「业务操作员」这类人；
- 叙述内高亮词用 `**粗体**` 成对标注；
- `>` 引用行放版本/日期/待裁数。

## 提炼纪律

1. **画像优先**。先写对头部四行与核心链路再动卡片——链路从文档「系统总览」章提炼；若原文档没有现成主链路，从功能域间的事实依赖关系归纳，并用【AI 推测】标注。头部四行回答「这是什么/解决什么/给谁用/不做什么」，全部来自文档的背景、用户与场景、明确不做什么各节。
2. **能力卡 ≠ 章节概要**。卡片不与文档章节一一对应：按叙事重组——**主线能力沿核心链路排前（从材料进来到交付出去，典型 4~6 张），支撑能力（质量闸、调优、配置底座等）靠后**；质量闸、调优、配置底座类能力即使与链路有触发关系，也归支撑组——主线只放「材料怎么进来、怎么变成结果、怎么交出去」的环节。相近或相邻的小域合并为一张卡；卡数与功能域数可以不同。每卡第一句必须回答「这环在整条链路里承担什么」。
3. **内容是精炼叙述，不是功能清单**。每卡 2~3 句融合的话：这环是什么、怎么运转、灵魂约束是什么。**参数级细节不进卡**——阈值数字、错误码、字段名清单、Qn 题号全部留给正文与问题清单；一页纸上只留构成画像的必要信息。禁止 bullet 式要点罗列。
4. **每句有据**。任何一句都能在原文档找到依据，不改口径；概括必须保住原文的限定词（「必须 / 禁止 / 显式失败 / 不产业务结论」这类词丢了就是改口径）。文档没有的信息不编造，确需归纳处标【AI 推测】。
5. **标识符与数字如实**。引用契约标识符（系统名、能力名）逐字；待裁题数、送裁/确认/填空的分布与原文档问题清单一一对得上。
6. **高亮克制**。每句最多 1~2 处 `**粗体**`，标概念与关键短语（如「样本反哺」「发布即固化」「目标冻结」），不标普通词。

## 自查（交付前过一遍）

- 只读这一页纸的人能复述出需求画像吗？主线讲通了吗？
- 有没有任何一句在原文档里找不到依据？限定词丢了吗？
- 参数级细节（数字阈值/错误码/Qn）混进卡里了吗？
- 待裁数字与原文档问题清单一致吗？
- 骨架语法（〔人工〕、（角色）、〔正文 N〕、`**`成对）逐条对了吗？
