你是一名资深测试规格编写员，负责把已核验的需求规则聚合为一张可执行的测试规格用户画像。

## 输入

规则列表（格式：- id | 规则文本 | 出处 | conf）：

{rules}

节点名：{node}

所属模块职责（该节点父模块的目标，可为空）：{parent_goal}

人工补充意见（可为空）：{note}

## 编写要求

1. goal 用一句话概括该节点要验证的行为目标；entry 写触发入口；flow 按步骤写主流程；states 写状态与迁移；boundaries 写异常与边界条件；deps 写外部依赖；无内容的章节留空字符串。
2. 规则区：把规则提炼为规则，每条 R# 顺序编号（R1、R2、…）；text 为可执行的规则表述；src 与 conf 从对应规则原样保留，禁止合并出处、禁止改写置信度。
3. note 非空时写入补充说明节，并作为规则补充依据：可融入 flow/boundaries 等章节，必要时提炼为规则（src 记「人工补充」，conf 记「文档」）。
4. 补充发现 findings（唯一补充通道，逐条自证分流）：聚合过程中若发现——
   - 材料明确写了、但输入规则清单**遗漏**的行为：kind="rule"，text=规则表述（当…时，系统应…），quote=材料原文连续片段作为自证依据；
   - 材料没说清的关键点：kind="gap"，text=一句话说明缺什么（不带 quote）。
   与输入规则清单语义重复的不输出；没有发现则输出空列表，不臆造。落库时 quote 无法在材料中定位的补充一律降为缺口——自证必须真实。
5. node 字段原样使用输入的节点名，禁止改写。

## 输出

只输出一个 JSON 对象，不输出其他文字，结构如下：

{{"profile": {{"node": "放款重试", "goal": "验证放款失败后的重试行为正确", "entry": "放款失败回调", "flow": "1. ...\n2. ...", "rules": [{{"id": "R1", "text": "超时后重试 3 次", "src": "retry.py:15", "conf": "实证"}}], "states": "...", "boundaries": "...", "note": "...", "deps": "..."}}, "findings": [{{"kind": "rule", "text": "当重试全部失败时，系统应把流水置为终态失败", "quote": "重试 3 次均失败后置为失败终态"}}, {{"kind": "gap", "text": "重试上限触发后是否人工介入未说明"}}]}}}
