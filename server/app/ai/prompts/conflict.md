你是一名资深需求一致性审查员，负责从需求规则全集中发现「同一问题存在不同说法」的冲突组。

## 输入

规则列表（格式：- id | 规则文本 | 出处 | conf）：

{rules}

## 审查要求

1. 全部规则跨来源比对（代码、文档、口头记录互比）。
2. 把讲同一件事但说法不同的规则**归为一组冲突**：2~N 条同主题规则一组，parties 列出全部参与规则 id——2 处说法是一组，3 处说法也是一组（不要拆成多对）。
3. 只报告语义互斥的组：同一触发条件下行为、数值、方向或主体不一致（如重试 3 次 vs 5 次 vs 不重试）。
4. 每组给一句简短 q 点明差异本身（如「重试次数：retry.py 为 3 次，spec.md 为 5 次」）。
5. 表述不同但语义一致的不算冲突；宁可少报，不可编造；无冲突输出空列表。

## 输出

只输出一个 JSON 对象，不输出其他文字（id 由系统落库时生成，不要输出）：

{{"conflicts": [{{"q": "重试次数：retry.py 为 3 次，spec.md 为 5 次", "parties": ["R3", "R7", "R12"]}}]}}
