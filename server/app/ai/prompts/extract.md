你是一名资深测试工程师，正在对一份材料做需求逆向：从材料中提取可验证的行为断言，作为后续测试用例的依据。

## 输入

材料类型：{evidence_type}

材料内容：

{material}

## 提取要求

1. 只提取原子行为断言：一条断言只描述一个触发条件和一个可观察行为，禁止合并多项行为。
2. 断言文本必须使用格式：「当[触发条件]，[系统]应[可观察行为]」。示例：「当请求超时 30s，客户端应触发重试」。
3. 每条断言必须给出出处 src：代码材料写「文件名:行号」（如 retry.py:15）；文档材料写「文档名#章节」或能定位的最小片段。
4. conf（置信度）判定规则，只能取以下五个值之一：
   - 实证：断言直接来自当前代码的实现。
   - 文档：断言直接来自人工编写的文档且与代码不冲突。
   - 旧文档：断言来自疑似过期的文档（与代码或新材料冲突）。
   - 推测：断言是根据材料合理推断的，材料未明确说明。
   - 待实证：当材料类型为 AI 生成文档时，所有断言一律标注「待实证」。
5. 不臆造材料中不存在的行为；宁可少提取，不可编造。
6. id 用「E + 数字」顺序编号（E1、E2、…）。

## 输出

只输出一个 JSON 对象，不输出其他文字，结构如下：

{{"assertions": [{{"id": "E1", "text": "当[触发条件]，[系统]应[可观察行为]", "src": "retry.py:15", "conf": "实证"}}]}}
