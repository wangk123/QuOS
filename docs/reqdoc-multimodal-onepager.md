# 瀚海多模态服务 · 需求一页纸

> draft-v1 · 2026-10-15 · 待裁 19 题

**这是什么**：瀚海智能助理系统的多模态能力服务——接收 PDF、图片、Office、压缩包、音视频等多形态材料，机器完成解析识别、分类、特征提取与结构化抽取，人负责确认与裁决，向尽调等被辅助系统交付结构化结果。
**解决什么**：多来源异构材料长期靠人工逐份查看、归类、抄录，口径不一且结果难追溯【AI 推测】→ 全链路自动解析与结构化抽取，结果带证据、经人工确认后固化发布、稳定交付下游。
**给谁用**：业务操作员、材料配置管理员、分类优化用户、外部被辅助系统（机器调用方）。
**不做什么**：不产出业务结论（特征只记事实、值、置信度与证据）；不代下游加工报文（CellMapper 由尽调侧自行展平）；不暴露内部标识（对外入参与响应均禁内部主键与存储地址）；不保留旧能力（材料核验移除、旧动态路径与旧列表页退役，口径送裁中）。

## 核心链路
上传/受理 → 解析识别（OCR / Office / 媒体三路由）→ 材料自动分类 → 人工确认〔人工〕→ 特征提取 → 结构化抽取 → 人工复核〔人工〕→ 发布固化 → 对外查询与 SSE 交付

对应正文 28 节点工作流：机器负责识别与计算，人负责确认与裁决；每次处理生成新 Run，历史不覆盖。

## 能力速览

### 主线 · 从材料进来到结果交出去
**受理单与影像树**（业务载体）〔正文 5〕：受理单是全部业务动作的载体，创建即固化影像树**结构快照**；影像树以节点「必需性 + 齐全性校验」两属性定义这笔业务要哪些影像、怎么算齐，缺必需影像时整单提交被拦截并给出缺失清单。业务按可配置阶段推进，页面上与确认相关的动作只有「确认影像分类」与「确认结果」两个。

**文档接入与解析**（入口标准化）〔正文 6〕：三个渠道（上传页、受理对话框、对外 API）进来的文件都经此转成可分类、可抽取的标准化内容——按类型分流 OCR、Office 原生解析或独立媒体路由，压缩包展开为子文件逐一独立派发。所有路径汇成统一的**文档证据档案**，证据全部 embedding 完成才 READY，之后共用同一套分类抽取尾段；解析失败显式留痕，OCR 误识别可在审阅工作台**人工修复**。

**材料分类**（定型）〔正文 7〕：冷启动评分与确认样本匹配**双路径并行**、仲裁汇合——达标自动确认、存疑转人工、交叉冲突一律转人工复核，人做终审。人工确认后的样本才入样本库**反哺**匹配，分类候选始终只来自已启用材料目录；外部任务显式指定材料时校验通过即直接定型，且不被自动分类覆盖。

**特征提取与媒体数据**（媒体归一）〔正文 9〕：音视频与图片先解析成**与 OCR 等价的标准数据**再进统一抽取链，特征模式与作用范围按材料配置。特征只记录事实、值、置信度与证据，**不产业务结论**；模型能力由目录声明、运行时校验，不匹配显式失败、不静默换模型。

**结构化抽取与结果交付**（核心产出）〔正文 8〕：把「这块材料里的这张表」变成带证据、可校验、可发布的数据——按「结果定义 → 结果块 → 结果字段」的层级先定位来源再召回字段，业务词全部来自配置、**禁止硬编码**。字段证据保留页码、坐标与原文，来源不唯一或证据不成立时显式失败，禁止全文回退与默认选首项。发布前过字段校验与数据勾稽两道门，人工复核通过后结果**发布即固化**、不可再改。

**对外 API**（交付出口）〔正文 11〕：构成被辅助系统全部可依赖的契约面——固定路径、POST 查询、写操作必带幂等键、SSE 事件通知。按分类取数以子文件为单位，多命中全部返回且顺序固定，未就绪单项带原因不影响其余，**命中为零与分类不存在严格区分**；响应中禁止出现内部主键与内部存储地址。

### 支撑 · 质量闸 · 调优面 · 配置底座
**影像合规审查**（质量闸）〔正文 10〕：按影像树规则集**自动重判**——新增影像、分类确认、人工修正等事实变化自动触发受影响影像补算，页面上没有用户「开始审查」按钮。当前落地的是轻量校验场景，完整审查引擎（状态汇总与受控检查类型）属目标态、未实现。

**智能分类助手与分类优化 Agent**（调优面）〔正文 12〕：Agent 负责取证与起草、系统负责**强制验证**、人负责终审；创建任务即**目标冻结**，改变目标必须新建任务。每个新草案自动执行案例真实试算与分类回归两项必验，全过且输入无漂移才进入待复核，模型自报完成无效；验证失败不是任务失败，失败草案携结构化反馈进下一轮，预算耗尽显式阻断。

**规则与配置管理**（配置底座）〔正文 13-14〕：勾稽与校验规则在画布设计器中设计、发布前强校验，由规则引擎在**发布门**前执行。服务端参数与材料级配置一处维护、运行期冻结快照，**保存不等于可运行**——配一半的定义被显式阻断而非跑出半成品；配置经 JSON 导出导入跨环境迁移。

**实时通知**（实时感知）〔正文 15〕：事件从业务事务内发出，经发件箱与广播送达各端 SSE，前端不直接消费事件数据而是**重读权威资源**。支持断线重放与事件去重；基础设施不完整时服务启动失败，而非静默降级。
