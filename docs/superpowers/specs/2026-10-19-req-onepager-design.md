# 需求一页纸（req-onepager）设计

> 2026-10-19，经 brainstorming 会话与用户对齐后成稿。渲染基准文档：`docs/reqdoc-multimodal.md`（v4，19 章 11 功能域，评测 944 分产物）。原型：`web/prototype/onepager-r1.html`。

## 意图与为什么

评审人打开一份几百行的需求文档（v4 基准 502 行 / 19 章）之前，需要 2~3 分钟建立骨架感：这份需求有哪些功能域、每个域干什么、边界在哪、这次要裁多少题。**需求一页纸**是文档的伴生概览产物——独立生成、独立查看，文档本体与批注评审工作流完全不动。

为什么是独立产物而不是融进文档渲染：评审平台的正文必须常驻（批注锚定挂在规则行、段落、表格字段上），卡片化概览塞进文档会干扰评审对象；独立出来后提炼的失真风险也被隔离在一页纸自己身上，正文永远是权威。

一页纸的内容组织是**画像式**（经用户三轮评审定调）：不是逐章概要的拼盘——看完一张张章节摘要，串不成整体认知；而是先整体后局部——这是什么、解决什么、给谁用，核心链路怎么转，能力块按「主线 → 支撑」的叙事顺序展开。呈现手法参考钉钉 AI 听记的结构化展示（卡片网格 + 行内关键词高亮），场景差异明确：纪要读者只要结论，卡片可以是全部内容；我们的读者是评审人，要裁对错——所以一页纸只做画像，细节留给正文。

## 目标

1. **评审前快速建立需求画像**：读完能复述「这个需求主要是做什么」——这是什么/解决什么/给谁用、核心链路怎么转、主线与支撑能力、边界、要裁多少题。
2. **结构化呈现**：文档头四行 → 核心链路（人工环节标注）→ 能力卡（主线/支撑两组，每卡一色+精炼叙述+关键词高亮）→ 场景速览 → 待裁统计。
3. **平台内独立查看**：评审页入口进入独立渲染页，不进批注工作流；点能力卡可跳正文对应位置。
4. **忠实**：每句能在原文档找到依据，数字与原文档一致（待裁题数与问题清单对得上）。

## 非目标

- 一页纸上无批注、无编辑；**唯一的交互是跳转**：点功能域卡跳正文对应章（用户确认保留，章号数字不显示）。
- 不改 req-organize / req-review（一页纸是新独立 skill，用户明确要求不往 req-organize 堆功能）。
- 不做文档页本身的渲染优化（该方向已放弃）。
- 不做导出 PDF / 图片（一页纸本身就是 md，复制即得）。

## 反目标（做成即失败）

- **膨胀成第二份文档**：叙述超过 3 句、参数级细节（阈值/错误码/字段名）进了卡，就失去画像价值。
- **章节概要拼盘**：卡与章一一对应、逐章摘要、读完串不成主线——与画像式目标背道而驰。
- **口径漂移**：短句改变正文语义、待裁数与问题清单不一致——比没有一页纸更糟（评审人带着错误理解进正文）。
- **静默推测**：无依据的短句不标【AI 推测】。

## 约束

- 平台不做 AI 加工（ADR 001）：提炼归 agent 侧，由新 skill 承担。
- 平台既有契约与工作流不破坏；一页纸全部可选——没有则功能降级隐藏，零迁移。
- md 是 agent 交付的通用形态：一页纸以 md 交付进平台。

## 方案

### 1. 生成侧：新 skill `req-onepager`

- 位置 `.agents/skills/req-onepager/SKILL.md`，单文件轻量：输入成稿需求文档 md（过完 req-review 门的），输出一页纸 md，一次提炼完成——不做评审、不做修复循环、不做多轮编排。
- 固定骨架（输出的 md 形态，也是平台渲染的解析依据；**画像式**——先整体后局部，读完后脑中有产品画像，而非逐章概要拼盘）：

```markdown
# {系统名} · 需求一页纸

> {版本} · {日期} · 待裁 {K} 题

**这是什么**：{一句话定位：给谁、做什么、机器与人怎么分工}
**解决什么**：{痛点 → 价值，一句}
**给谁用**：{用户类列表}
**不做什么**：{2~4 条边界}

## 核心链路
{材料进入 → 解析识别 → 人工确认〔人工〕 → … → 交付：节点以 → 连接，人工环节节点尾缀〔人工〕}

## 能力速览

### 主线 · {从材料到交付}
**{能力名}**（{角色}）〔正文 {章号或章号范围}〕：{2~3 句精炼叙述，讲这环是什么、怎么运转、关键在哪；高亮词 **粗体**}

### 支撑 · {质量与运转}
**{能力名}**（{角色}）〔正文 {章号或章号范围}〕：{同上}

## 场景速览
{M 个场景名一行带过，详见正文}

## 待裁事项
送裁 {X} · 确认 {Y} · 填空 {Z}——评审前先看文档末问题清单
```

- 提炼纪律（skill 的核心内容）：
  - **画像优先**：核心链路从「系统总览」章提炼（一条链 + 人工环节标注）；一页纸的成败在读完后能否复述「这个需求主要是做什么」。
  - **能力卡 ≠ 章节概要**：卡片不与文档章节一一对应——skill 按叙事重组：主线能力沿核心链路排前（从材料进来到交付出去），支撑能力（质量闸、调优、配置底座等）靠后；相近/相邻的小域可合并为一张卡，卡数与域数可以不同。顺序服务理解，不等于章序。
  - **内容是精炼叙述，不是功能清单**：每卡 2~3 句融合的叙述——这环是什么、怎么运转、灵魂约束是什么；**参数级细节不进卡**（阈值数字、错误码、字段名清单、Qn 题号——留给正文与问题清单），卡上只留构成画像的必要信息。引用任何标识符仍逐字不失真。每张卡带〔正文 N 章〕标注（合并卡给章号范围），平台据此实现点卡跳转正文对应章。
  - 每句须能在原文档找到依据，不改口径；概括须保持原文档的限定词（「必须 / 禁止 / 显式失败」不能丢）。
  - 数字如实（待裁题数、域规模类数字照抄）；素材未支持的内容标【AI 推测】。
  - **高亮词由 skill 在 md 里以 `**粗体**` 标注**（概念与关键短语，如「样本反哺」「发布即固化」「目标冻结」）——前端不猜高亮，只渲染标记；粗体在 md 里本身就是强调语义，脱离平台阅读也成立。

### 2. 平台侧：伴生存储与独立查看

- **契约**：`POST /doc/draft/import` 与 `POST /doc/draft` 请求体增可选字段 `one_pager_md`；drafts / versions 表加独立列存储（一页纸不入 payload——它是伴生物，不是文档结构的一部分）。SQLite 既有表加列需启动时幂等 ALTER 补列（`create_all` 不会给既有表加列）。
- **API**：
  - GET 草案响应带出 `one_pager_md`，无则 null；
  - `POST /doc/finalize` 定稿时把 reviewing 草案的 `one_pager_md` **复制进 version 行**（定稿请求体不带一页纸，来源唯一=草案），否则定稿后入口消失；
  - `GET /doc/baseline` 响应带出（基线只读态也有一页纸入口）；`GET /doc/versions` 列表端点**不带**全文 md（列表轻量）；
  - `docs/api.md` 同步以上全部。
- **前端**：评审页工具条加「一页纸」入口（可见性判定：draft 或 baseline 任一带 `one_pager_md` 即显示）→ 独立渲染页按骨架解析 md 渲染：域色编号徽章 + 白卡网格（两列，末卡可通栏）+ 短句内 `**粗体**` 渲染为域色高亮 + 短句尾 `(Qn)` 渲染为浅灰题号引用 + 文档头（一句话/边界 chips/统计）+ 底部（用户场景摘要条 + 待裁统计块）。
- **生命周期**：文档重导/重新提交时一页纸随之覆盖更新（同一伴生位，非追加）；定稿随 finalize 冻结进 version。
- **降级**：存量草案与不带 `one_pager_md` 的提交，入口隐藏，其余一切不变。

### 3. 渲染样式（以原型 R3 为基准，实施时可微调）

- 页面结构（画像式）：**文档头（这是什么 / 解决什么 / 给谁用 / 不做什么）→ 核心链路（一条横向流程链，人工环节琥珀色标注 + 一句分工原则）→ 能力速览（「主线」「支撑」两组卡网格，卡片顺序=skill 叙事序）→ 场景速览一行 → 待裁统计块**。
- 能力卡：**叙述式段落呈现**（非 bullet 清单）——卡头（能力名 + 角色标签 + 「正文 ↗」跳转入口）+ 卡身 2~3 句精炼叙述；无章号数字（经用户评审否决）。
- 域色：每张能力卡一色（原型提供色板，卡数超出时循环），左缘色条、角色标签、行内关键词高亮统一取该色。
- 关键词高亮来源：**md 里的 `**粗体**` 标记**（生成侧标注，前端只渲染不识别）。
- 整页两色系基调：浅灰底 + 白卡 + 域色强调 + 人工环节琥珀，无其他装饰。

- `one_pager_md` 的校验（类型、长度上限）与错误处理（非法时拒收还是忽略转警告）。
- 渲染组件拆分、评审页入口形态（按钮 / 标签页 / 弹层）。

## 我替你做的两个决定（builder check 提出，请过目）

1. **定稿后一页纸不丢**：finalize 时从草案把 `one_pager_md` 复制进 version，`GET /doc/baseline` 也带出——否则发版后评审页常态（看基线）没有一页纸入口。versions 列表端点不带全文，保持轻量。
2. **高亮词由 skill 写进 md（`**粗体**`）而非前端猜**：原型里「显式失败」「目标冻结」这类语义短语前端正则识别不出来，只有生成侧标注才稳定；粗体在 md 里本来就是强调，脱离平台阅读也成立。（注：Qn 题号引用不进卡——待裁细节留给正文与问题清单，与提炼纪律一致。）

## 验收画面

拿 `docs/reqdoc-multimodal.md`（v4）走 req-onepager 产出一页纸 → 随文档导入平台 → 评审页点「一页纸」→ 评审人 2~3 分钟读完：能复述「这是给尽调做材料结构化的流水线服务，机器识别计算、人确认裁决，主线从材料进来到 API 交付，支撑面有质量闸与调优」，能力卡点得进正文对应章，待裁 19 题与问题清单一致——然后带着画像进正文开始评审。
