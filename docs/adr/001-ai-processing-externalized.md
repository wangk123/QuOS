# ADR-001: AI 加工外部化,平台转为「接口 + 校验 + 闸门」

日期:2026-10-14 · 状态:已接受

## 决策

平台不再内置 LLM 编排(v1 `server/app/ai/` 的 understand/extract/verify/conflict/gap/assemble/impact 七任务全部废弃)。需求整理等加工由外部 agent 结合项目内 skill(`.agents/skills/req-organize` 等)执行,通过平台统一接口提交产出;平台对提交物做两级校验(硬错误拒收 / 软警告转人闸门)。

## 背景

v1 的 AI 参与形态是单发 LLM 调用:无消歧闭环(题目越堆越多)、无整文自查、质量无裁判。而格式与可判定标准硬编码在 prompt 里,属于「软约束」——AI 可以不听,平台照单全收。

## 理由

1. **约束从软变硬**:接口校验让不符合标准的产出进不来,质量守恒(每减少一分人的参与,必须补一分机器可执行的验证)有了唯一落点;
2. **加工能力升维**:外部 agent 具备多轮迭代、读文件、跑工具的能力,消歧循环与整文自查这类闭环工作单发 API 调用先天做不了;
3. **标准外置可迭代**:加工方法沉淀在 skill(md 文件),迭代成本趋近于零,不受平台技术栈限制;
4. **解耦「谁加工」与「怎么管」**:平台是唯一真相源与守门员,agent 无状态、可替换。

## 后果

- v1 AI 编排层不迁移,直接删除;
- 平台技术栈不再包含 LLM 网关依赖;
- skill 与平台接口契约必须配套演进(接口变更时同步改 skill 的对接章节);
- 远期如需平台侧触发/嵌入 agent,是新增能力,不影响本决策的地基。
