# ADR-002: SQLite 为唯一真相源,版本平台自管

日期:2026-10-14 · 状态:已接受

## 决策

v2 采用 SQLite 单文件库为唯一真相源,存储:材料元数据与解析文本、文档版本快照、条款级变更记录、题目与答案、规则条目库。原始材料文件(pdf/图片等二进制)存文件系统,库内只存路径与 hash。废弃 v1 的「文件系统 json/md + 每项目 git 仓库基线 + MySQL 元数据索引」三层结构。

## 理由

1. **文档版本不依赖 git**(用户明确):版本管理由平台自管——每次定稿存整份文档快照,变更记录按条款记差异(编号/旧文/新文/原因/批准人),diff 由快照对比生成;
2. **单人本地场景**:SQLite 零运维、零服务依赖,备份即拷贝单文件;MySQL 的并发能力用不上,却多一个服务依赖与「真相源/索引」双层一致性负担;
3. **二进制不入库**:材料原始文件留在文件系统,库内 hash 校验完整性。

## 后果

- 不再为每个项目维护 git 仓库,无 git 操作失败分支;
- 文档导出 md 为只读副本,不是真相源;
- 不可达降级、目录扫描等 v1 容错逻辑不再需要;
- 若未来多用户/多机部署,需重新评估数据库与并发(本 ADR 范围外)。
