# QuOS · 需求文档

> 本文为产品需求唯一权威文档（2026-10-12 汇总重写），整合历次 spec 演进的最终态；过程性 plan/spec 已归档删除。
> 当前版本 v1.0.0（M1 reqspec），基线 commit cafcd1b，后端 205 / 前端 87 测试全绿。

## 1. 定位与设计哲学

**质量操作系统**：全质量域模块化集成（需求整理、案例设计、缺陷管理、回归自动化、性能、安全），为 AI 深度协作的测试流程设计。当前单人使用与开发，架构不设单人限制。

设计背景：需求输入碎片化（无文档 / 过期 / 开发过程 / AI 生成 / 口头为主）、开发全员 AI 辅助节奏快、测试对流程无强制约束力。

五条设计哲学（全平台通用）：

| # | 哲学 | 内容 |
|---|---|---|
| 1 | 资产统一 | 一棵功能树贯穿全程：需求画像挂叶子 → 案例组挂画像 → 缺陷聚集挂模块 → 回归范围 = 受影响子树 |
| 2 | 文件为源 | Markdown + git 是唯一真相源，平台只是编排器和视图层；MySQL 等仅做可重建索引 |
| 3 | AI 编排化 | 每个动作一个 AI 任务，prompt 模板即流程知识，版本化积累 |
| 4 | 闸门内建 | 人工闸门（核验/裁决/采纳）是平台功能不是自觉——AI 幻觉/漏扫靠闸门兜住 |
| 5 | 判断复利 | AI 出初稿、人做砍/补/锚，判断沉淀为规则与修正留痕反哺后续流程 |

人机分工：AI 供给规模、一致性、速度；人供给私有历史、领域不变量、组织现实、责任签名。界面固定范式：AI 初稿 → 人砍/补/锚 → 判断留痕沉淀。

用户定位（已裁定）：为测试工程师服务，产物 =「我的理解基线」；AI 展开 + 核验链是差异化灵魂。

## 2. 总体架构

```
内核（功能树 / 证据池 / 基线 git / AI 编排器）
  └── 模块（可插拔）：reqspec（当前）· casegen · defect · rerun · perf · sec
```

模块 = 统一节奏：选目标节点 → AI 生成初稿 → 人工闸门 → 产出资产挂树 → 并入基线。

## 3. 项目管理（多项目）

- 项目首页：列表（按最近打开排序）/ 新建（名称必填、描述可选）/ 折叠归档区
- 项目身份 = `server/data/<slug>/` 目录；归档 = 目录移入 `data/.archived/`；彻底删除仅限归档态、输名确认（`rm -rf` 含 git 基线历史）
- 项目编辑：改名（slug 目录身份不动）/ 改描述；卡片删除输名确认走归档→删除链
- 手工创建的目录自动成为项目（`project.json` 缺失时目录名兜底）
- MySQL 只存可重建元数据索引（projects 表）；不可达自动降级目录扫描，核心流程不受阻

## 4. 需求工作台 reqspec（M1 核心模块）

### 4.1 交互范式：文档生长（非步骤导向）

用户唯二主动动作：① 导入材料（拖拽 / ⌘V / 粘贴 git）② 点「生成需求」。其余后台自动：大纲先出 → 细节逐节点流式完善 → 完成一块展示一块。

两态界面：
- **落地态**：空项目 = 整页大导入框；有材料 = 追加条 + 材料列表 + 「✦ 生成需求」
- **工作台态**：左大纲树（58%，独立滚动）+ 右节点详情（42%，sticky 独立滚动）；顶栏 = 项目名(v#) / 版本 / 证据池(n)

材料智能识别（入池自动分类）：`git@`/`.git`/git 托管链接 → 仓库（尾部 `feature/xx` 解析分支）；⌘V 图片 → 截图；其他文本 → 文本材料；拖入文件按扩展名归档。多模态解析：docx 剥 XML、pdf 走 pypdf（扫描件提示转图片）、图片多模态直读（长边 >1600px Pillow 压缩）。

### 4.2 大纲树（三层语义）

| 层级 | 内容 |
|---|---|
| 根卡片 | 需求一句话（这是什么）、给谁/边界、全局统计（条目数/待判断数） |
| 模块卡 | 名称 + 职责一句话 + 徽章（条目/待判断） |
| 叶行 | 名称 + 一句话 + 徽章（条目/待判断/⚠冲突/画像✓） |

- 树即需求文档本体：hover ✎ 行内编辑名称/描述/结构（改名/加子/删除），无采纳闸门
- 一句话 = 节点画像 goal 首句，树上编辑即编辑 goal，不新增树字段
- 徽章 = 工作清单：待判断（琥珀）、冲突红⚠、缺口△、画像就绪绿✓
- AI 生成大纲仅树空时提供；树节点带材料出处（cite 校验防幻觉）

### 4.3 节点详情

- 面包屑 + 节点三态：排队 → 处理中（骨架屏）→ 就绪
- **概要 tab**：goal / 入口 / 主流程 / 状态机 / 异常 / 依赖（画像字段直出）+「待你判断」汇总卡
- **规则 tab**（条目与存疑已合并）：状态 chips（全部 = 核验通过 + 待处理 / 待处理 / 已核过）+ 核验进度条 + 规则行（要求 / 出处溯源 hover / 置信度徽章）
  - 规则行内动作：核验（单条）、✎ 编辑（标黄留痕）、✕ 删除（二次确认）、＋新增规则（手动记规则）
  - **冲突卡**：默认折叠（`⚠ C1 · 题干摘要`），展开显示 N 方说法（选项 = 规则编号 R#，带 ↗ 跳转直达规则所在节点）+ 信 A/信 B… + 「其他」手输（生成人工确认实证规则，各方作废）；已裁决灰行留痕
  - **缺口行**：判读为设计如此 / 补写闭环（补写文本落实证规则）；材料已补自动闭环显示「材料已补 ✓」
  - 已处置疑点收进底部折叠留痕区（毕业不计数）

### 4.4 生成与重新生成

- **一键生成**（generate job）：understand（产树+根画像+初始画像）→ 逐材料 extract+verify → conflict 重扫 → 逐叶 assemble（未核条目跳过不组装，闸门数据化）→ gap 重扫 → summary 聚合
- 长任务 job 化：状态落盘可恢复、分批真实进度、SSE/轮询、可取消（已完成保留）
- **重新生成两模式**（证据池发起）：
  - **全量重新生成**：人工强制；明示「人工修改会被重新组织，不保证保留」
  - **✦ 智能生成**（smart）：一次 job 六阶段——① 新材料提取+自核验 → ② 遗留未核验规则全量重核 → ③ resolve-doubts（遗留 open 冲突+缺口 × 全池材料，材料有明确依据才自动裁决/闭环，否则 keep 不静默拍板）→ ④ 影响分析（全自动采用）→ ⑤ 受影响节点重组装 → ⑥ 模块/根画像聚合刷新；job 透出 `auto_resolved` / `auto_closed` / `regen_nodes` 消解清单
- 生成中可编辑已完成/排队节点；处理中节点编辑置 pending 完成后重跑

### 4.5 疑点直处体系（已裁定终态）

疑点出路只有两条：**当场处置**（裁决 / 核验 / 判读 / 补写 / 自动闭环）或**保持待处理**；材料更新后走重新生成消解。问人中间态（转待确认/转澄清/AI 代答采纳）已整体退役（2026-10-10）。

冲突 = 多方归组：同主题 2~N 条说法归为一组冲突（`parties`），题干+各方对照裁决；归属 = 参与规则节点中最深有效节点（孤儿/无归属 → 全局区）。

### 4.6 证据池（顶栏弹窗）

追加材料区 + 列表（类型 / 星级可信度 / 已并入状态 / 删除）+「↻ 重新生成」两模式入口。可信度分治：代码 > 实际系统 > 口头 > 开发文档 > 旧文档 > AI 生成文档（最危险，强制待实证逐条核实后才升级）。

### 4.7 版本管理（基线 git tag）

- 版本号手动输入 `x.y.z`（tag = `v{x.y.z}`），三重校验：格式合法 / 不重复 / 不低于已有最大版本（旧 `vN` 映射 (N,0,0) 兼容显示，不参与倒挂比较）
- 新增版本表单（版本号实时校验红绿反馈 + 纯文本说明）；存版恒建 commit（无变更建空 commit，保证说明随版本落档）
- 时间线：版本号 · 时间 · commit 短哈希 + 说明；HEAD 所指行绿点「当前」徽章
- **回滚**：二次确认后 `reset --hard` + `clean`，未存版修改丢弃不可恢复（明示）
- **废弃**：`git tag -d`，从时间线彻底消失；commit 仍在 git 历史可手动找回

### 4.8 需求文档导出（面向人的交付物）

`/doc` 导出 markdown，**文档是生成物不手工编辑**。面向人原则（已拍板）：大纲树/规则等是过程产物，文档生成须净化重组、不必与过程字段硬性一致；来源/置信度/验证措辞/计数等过程字段默认不进文档。

文档结构：文档头（项目名 / 版本接当前基线 / 生成时间 / 范围统计）→ 按树分层章节（标题用节点名不拼全路径）→ 规则列表化去 ID → 状态机按组拆行 → 孤儿画像收附录；验证句式去壳（「系统应验证X」→「X」）、计数型边界过滤、「验证码」名词排除。

预览弹窗：宽 1240px + 右侧章节导航（h2-h4，点击手动偏移滚动 + 滚动高亮当前章 rect 口径）；渲染 ⇄ 源码切换；受限 md 渲染器（标题/列表/表格/行内粗体，全量 HTML escape 后组标签，不新增依赖）；下载文件名带版本号。

## 5. AI 引擎

### 5.1 编排器（API 直连链路）

任务注册表，prompt 模板存 `prompts/` git 版化：

**规则质量规范**：原子行为规则格式 =「当 [触发条件]，[系统/组件] 应 [可观察行为]」（✗「支持重试」不可判定；✓「当放款回调超时 30s，重试服务应以相同流水号重发，上限 3 次」）；每条强制带出处（`文件:行号`/`文档§节`/`口头·日期`）。置信度五级：实证（绿）/ 文档（蓝）/ 推测（琥珀）/ 待实证（红，AI 生成材料产出强制打此级）/ 旧文档（灰）。

| 任务 | 输入 → 输出 | 闸门 |
|---|---|---|
| understand（树空时） | 证据池全量 → 树骨架 + 根画像 + 节点初始画像 | 全部推测级，人工编辑 |
| extract | 材料 → 规则[]（内容+出处+node 归属） | 服务端校验 node ∈ 树白名单 |
| verify | 未核规则 × 材料 → 核验结果+quote；读错的当场修正规则文本并黄标留痕，输出核验记录；可 only_doc 跳过推测级 | quote substring 校验 |
| conflict | 规则全集 → 同主题多方冲突组 | 人工裁决 |
| gap | 节点画像摘要 × 维度清单 → 缺口[] | 人工判读（预置六维：状态/异常/边界/幂等/数据/依赖，项目级可配） |
| assemble | 节点规则 + 父节点 goal → 画像草稿 | 未核条目跳过不组装 |
| summary | 子节点画像聚合 → 根/模块画像 | 随存档/局部重生成刷新 |
| impact | 新材料提取结果 + 现有规则 → 受影响清单 + 方案 | smart 内部自动采用 |
| resolve-doubts | open 冲突+缺口 × 全池材料 → auto/keep 判定 | winner∈parties + quote 定位校验，失败降级 keep |

### 5.2 Agent 引擎（dsh headless，大输入任务）

understand / extract / verify / resolve-doubts 四个大输入聚合任务可切内嵌 agent 引擎（agent 自管上下文，平台不做分片截断）。`QUOS_DSH_CMD` 未配置时自动 off 降级 API 链路。

ATD 任务目录协议（引擎可替换的稳定契约）：`TASK.md`（运行时参数）+ `RULES.md`（引擎无关规则模板）+ `materials/`（材料文件+manifest）+ `out/result.json`（产物，ingest 白名单校验后按现有模型入库）+ `out/report.md`（agent 自评留存）。

安全缓解链：材料=数据非指令声明 + cwd 隔离 + 环境变量白名单 + ingest 白名单兜底。硬规则：不臆造（每条产出给 ev_id+原文引用，给不出依据自己删）、生成后对照材料目录自评覆盖、result.json 严格 schema。

## 6. 数据资产（文件布局）

```
server/data/<slug>/
 └─ project.json          项目元信息（name/description/created_at）
 └─ tree.md               功能树（任意层级嵌套）
 └─ profiles/<节点>.md     画像（R# 规则、出处、置信度、补充说明；__root__.md 为根画像）
 └─ rules.json / conflicts.json / gaps.json    规则/冲突/缺口
 └─ evidence/             证据池（原始材料 + files/ + index.json）
 └─ git 仓库（.git）       基线（commit + tag）
```

核心对象：Evidence(id,name,type,stars,source) · Rule(id,text,src,node,conf,verified,nb) · Conflict(id,parties[],q,st,resolution,manual_text) · Gap(dim,text,node,st) · Profile(kind: root|module|leaf, goal/entry/flow/state/excp/deps) · Baseline(tag,version,commit,time,note,cur)。

存量兼容策略：模型演进一律 pydantic 默认值兜底 + 读侧归一（旧 a/b 冲突 → parties），**零数据迁移写回**；退役字段/文件保留不读可追溯。

## 7. 计数与徽章口径（唯一权威口径，回归即 bug）

- **总数 = 已核过 + 待处理**；待处理 = 有效规则中未核（含「冲突中」参与规则）+ open 冲突 + open 缺口；跨节点冲突参与方计入其所在节点
- 树行 / tab 角标 / 标题 / chips / 行数 **五处同数**；tab 数 = 树行 N 条口径（不混入冲突缺口数）；模块 = Σ叶 + 自身，Σ树 + 全局区 ≡ 总 stats（恒等式测试钉死）
- 徽章归属单一实现：冲突 = 参与规则最深有效节点；缺口 = 绑定节点；孤儿/无归属 → 全局区
- 已处置疑点进留痕区不计数

## 8. 路线（M2-M6）

节奏：每个模块先原型验证 → MVP（跑通闭环）→ 打磨；模块间不阻塞，可并行。

- **M2 casegen 案例设计**（下一模块，设计共识已定）：挂接画像树；C↔R 双向追溯（砍案例自动暴露无覆盖规则）；分层生成（高风险完整用例 / 中低 checklist / 紧急纯探索）；类型配额 主路径:异常:边界 ≈ 2:4:4、每叶案例上限 12；分块评审（5-15 条/块，5-10 分钟时间盒，整块通过/降级/舍弃，未审完的块自动按 AI 建议优先级走——决策显式）；案例条目格式 `ID | 优先级 | 类型标签 | 一句话（含关键数据）`；优先级 P0 不变量+高风险边界 / P1 异常+状态转换 / P2 主路径 / P3 边缘（节点级，案例继承）；AI 任务：casegen（画像+规则→案例树）、quota-check、coverage-map
- **M3 defect**：缺陷挂树节点、聚集分析（80/20）反哺风险分级；每缺陷问「本可如何发现」→ 预防规则入判断规则库
- **M4 rerun**：事件驱动回归（变更 → AI diff 定位受影响子树 → 激活案例组）；接口自动化资产库个人可带走
- **M5 perf / M6 sec**：远期模块化接入，共享树与基线

依赖：M1 → M2 → M4；M3 可与 M2 并行；M5/M6 独立可插。

## 9. 非功能需求与已知限制

| 项 | 要求 |
|---|---|
| 技术栈 | Vue3 + Vite / FastAPI + pydantic v2 / 文件系统 + git 真相源 + MySQL 可选索引 / LLM OpenAI 兼容接口 |
| 部署 | 本地单机 localhost（8000 端口，start.sh 一键），零运维；架构允许后续服务化 |
| 交互底线 | 完整交互不许静态假图；人话命名；IDE 级 UI 规范 |
| 数据可迁移 | 平台挂了数据还在（文件为源）；导出 md 不锁死 |

已知限制：
- 生成中编辑根节点 goal 会被后台 summary 覆盖（生成中避免编辑处理中节点）
- 全量重新生成不保证保留人工修改（智能生成保留人工判断）
- 单人单机，不做并发锁
- 扫描件 PDF 提不出文本（提示转图片）；仓库/压缩包材料不入 AI 提取
- 暂无 LLM 调用观测（tracing）与 prompt 回归评测护栏（候选 Opik/promptfoo，多 agent 成型后再评估）

未决问题：
1. 判断规则库的存储格式与注入点（三层法机制已定：做了什么判断 → 依据什么模式 → 写成 if-then；目前以规则修正/手动记规则留痕承载，未独立资产化）
2. casegen 评审界面形态、案例执行状态流转、与 M4 回归的衔接字段
3. M4 事件订阅触发通道（commit webhook / 手动粘贴）
4. 多人/团队化的架构预留边界（仅约定不设单人限制，未做具体设计）
