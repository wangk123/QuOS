## 2 背景与目标

**痛点**：风控云账号当前仅凭密码即可登录，存在三类已识别的安全风险——短信接口可能被盗刷、弱密码易被猜测或撞库、密码长期不修改导致泄露后长期有效。

**目标**：在登录链路上叠加图形验证码与短信验证码两道校验以压缩盗刷与撞库空间，并通过密码过期强制修改与密码复杂度校验消除弱密码与长期不改密的存量风险；同时补齐用户手机号维护能力，保证短信验证码可达。

**成功标准**：素材未给出可度量或可判定的验收指标（见 TBD-01），待用户方补充后回填本节。

**明确不做什么**：
- 不改造原有密码登录主流程、菜单权限及业务功能（素材明确「保持不变」，作为回归基线而非本期需求）；
- 不涉及风控业务功能本身的安全改造；
- 不含短信通道自身的建设（阿里云短信为外部采购能力，仅做配置接入）。

### 3.2 端到端场景

**场景 1（U1，短信验证码开关开启·正常登录）**
工作日早晨，风控运营人员打开风控云登录页，输入账号与密码。页面要求先通过图形验证码，他看不清图，点击验证码图片刷新了一张（后端重新生成 SVG）。图形验证码通过后，「获取短信验证码」按钮可用，点击后按钮进入倒计时，页面弹出提示「已向138****2344号码发送短信，请注意查收」——手机号是脱敏的。他从手机收到 6 位验证码并回填提交，密码与短信验证码均正确，登录成功，进入风控云菜单。
异常分支：图形验证码填错或已过期时，点击获取短信不生效；倒计时未结束再点按钮无法重发；当日该手机号发送次数达到上限后不再发送；短信验证码填错、超时或尝试次数超限则校验失败，登录被拒绝。

**场景 2（U1，密码过期·强制改密）**
某用户密码已连续数月未修改，超过配置周期。他照常输入密码、通过图形验证码与短信验证码，**账号仍可正常登录**——但登录成功瞬间前端弹出修改密码弹窗并阻断后续操作：不完成改密，菜单和任何业务页面都无法进入。他在弹窗中填写旧密码、符合复杂度的新密码，再点击获取短信（此处无需再过图形验证码，但同样有倒计时），输入短信验证码后提交，改密成功，弹窗关闭，正常使用系统。
异常分支：新密码缺少数字/大写字母/小写字母/复杂符号任一类时无法提交。

**场景 3（U1，短信验证码开关关闭·兼容登录）**
短信通道故障期间，配置管理员在 Apollo 关闭短信验证码开关。用户登录时不再出现短信验证码环节，只需账号、密码和图形验证码即可登录；登录后菜单权限与原有业务功能与改造前完全一致。
异常分支：图形验证码错误时登录被拒绝（行为与改造前图形验证码逻辑一致）。

**场景 4（U2，维护用户手机号）**
某用户换了手机号收不到验证码，找系统管理员处理。管理员打开用户管理页面，找到该用户，修改手机号并保存；系统同步更新账号表中的手机号。之后该用户登录获取短信、强制改密收短信，都发到新号码。页面提示与操作日志中，手机号一律脱敏显示。
异常分支：素材未定义手机号格式校验失败与保存冲突时的行为（见 TBD-12）。

**场景 5（U3，上线配置）**
上线前，配置管理员在 Apollo 完成短信验证码开关、阿里云短信、限流与密码过期参数的配置并发布；真实 app-key/app-secret 由其维护，不进入代码仓库。他确认阿里云 AccessKey 具备发送短信的最小权限、短信签名与模板 SMS_512135018 已审核可用、Guard 账号表测试账号已配置有效手机号、MongoDB 账号可读写 auth_challenge 集合后，通知测试开始验证。

## 4 系统总览

### 4.1 系统是什么

风控云在原有账号密码登录之上叠加「图形验证码 + 短信验证码」两道校验：短信验证码开关开启时密码与短信验证码双因子放行；关闭时退化为密码+图形验证码的兼容模式。配套引入密码过期强制修改（含密码复杂度校验）与用户手机号维护。校验与账号能力由 Guard 认证及账号管理模块承接，验证码短信经阿里云短信通道下发，开关与参数由 Apollo 配置中心管理。

### 4.2 主链路（短信验证码开关开启·登录 → 强制改密）

```
打开登录页 → 输入账号/密码 → 通过图形验证码校验
  → 点击「获取短信验证码」（按账号倒计时 / 单手机号每日上限）
  → 服务端生成6位验证码 → 阿里云短信下发 → 页面提示脱敏手机号
  → 输入短信验证码 → 校验（密码 ∧ 短信验证码 ∧ 尝试次数未超限）
  → 登录成功
      ├─ 密码未过期 → 进入系统
      └─ 密码过期   → 强制改密弹窗（阻断后续操作）
                        → 输入旧密码 + 新密码(复杂度校验) + 短信验证码(免图形验证码，有倒计时)
                        → 改密成功 → 进入系统
```

短信验证码开关关闭时主链路退化为：`打开登录页 → 输入账号/密码/图形验证码 → 校验通过 → 登录成功 →（密码过期则同上强制改密，改密短信要求见 TBD-05）`

### 4.3 上下文图（系统边界与数据流向）

```
U1 登录用户 ──账号/密码/验证码──▶ ┌──────────────────────────────┐
U2 系统管理员 ──用户手机号变更──▶ │ 风控云                        │
                                 │  前端 cloud                   │
Apollo 配置中心 ──开关/参数流入─▶ │  管理端 hsjry-risk-cloud-admin │
                                 │  Guard 认证及账号管理模块       │
                                 └──────┬───────────┬───────────┘
                                       │ 验证码短信  │ 验证/挑战记录读写【实现反推：
                                       ▼           ▼   素材仅提 auth_challenge 集合权限】
                                 阿里云短信服务   MongoDB(auth_challenge)
                                       │
                                       ▼ 短信下发
                                 用户手机（脱敏号提示展示于页面）
账号表：手机号、pwdUpdateTime、密码 —— 由 Guard 账号管理模块读写
```

### 4.4 核心数据实体

| 实体 | 关键属性（素材可见） | 关系 |
|---|---|---|
| 账号 | 密码（MD5 提交）、手机号、pwdUpdateTime | 1 个账号绑定 1 个手机号；多账号可同手机号（维度冲突见问题清单第 15 题） |
| 短信验证码记录 | 6 位数字、有效期、尝试次数 | 归属账号/手机号；存储于 auth_challenge 集合【实现反推】 |
| 图形验证码 | SVG、有效期 | 一次性使用（错误/过期/重复使用即失效） |
| Apollo 配置项 | 见 5.2 参数表 | 控制上述行为的开关与数值 |

## 5 需求主体

### 5.0 跨域通用规则

- **GP-01** 手机号在页面提示与日志中一律脱敏显示，不出现完整手机号（登录提示场景的实例见 FR-205）。
- **GP-02** 短信验证码开关的启停不改变原有密码登录、菜单权限及业务功能的行为。

### 5.1 登录身份校验

**为什么存在**：服务 U1 的登录场景（场景 1/3）。原单一密码因子是盗刷与撞库风险的入口，本章定义两种开关模式下登录放行的判定行为。

**叙述**：登录需要几把钥匙取决于 Apollo 短信验证码开关——开启时是「密码 + 短信验证码」双因子（短信验证码的获取前置见 5.2）；关闭时退回「密码 + 图形验证码」，且原有登录后行为完全不变。

**行为级规则**：

- **FR-101** 短信验证码开关开启时，密码登录必须同时填写短信验证码，密码与短信验证码均正确才能登录成功。
- **FR-102** 短信验证码开关关闭时，登录不再要求短信验证码，仅校验密码与图形验证码。

**异常路径**：
1. 密码错误 → 登录失败（原有行为，本次不变）。
2. 短信验证码错误/过期/尝试次数超限 → 校验失败，登录拒绝（展开见 5.2 FR-206）。
3. 图形验证码错误 → 登录/获取短信被拒绝（见 FR-201）。

### 5.2 短信验证码获取与发送控制

**为什么存在**：服务 U1 的场景 1/2。短信通道是付费且有盗刷风险的外部资源，本章约束「谁能发、多久发一次、发多少、发给谁看」。

**叙述**：图形验证码是人机校验的第一道闸，通过后才能触发短信；短信按账号倒计时、按手机号限额；发送成功只向用户展示脱敏号；验证码本身由服务端生成且有时效与尝试次数约束。

**主链路**：`图形验证码校验 → 触发短信（倒计时/每日限额闸门）→ 服务端生成6位码 → 阿里云下发 → 脱敏提示 → 用户回填校验`

**行为级规则**：

- **FR-201** 获取登录短信前必须先完成图形验证码校验；图形验证码错误、过期或重复使用时不能发送短信。
- **FR-202** 图形验证码由后端生成 SVG，支持点击刷新。
- **FR-203** 短信获取按钮按账号执行倒计时，倒计时期间不能重复发送。
- **FR-204** 单手机号每日短信发送设上限，达到上限后不能继续向该手机号发送。
- **FR-205** 短信发送成功后向用户显示脱敏手机号提示（样例形态「已向138****2344号码发送短信，请注意查收」）。
- **FR-206** 短信验证码错误、过期或超过最大尝试次数时校验失败。
- **FR-207** 短信验证码由服务端生成，为 6 位数字，短信模板参数仅包含 code。

**参数表（Apollo，含义按参数命名推断【推测】，未经需求方确认）**：

| 参数 | 默认值 | 含义（推测标注） |
|---|---|---|
| security.sms.enabled | true | 短信验证码开关 |
| security.sms.code-expire-seconds | 300 | 短信验证码有效期（秒）【推测】 |
| security.sms.captcha-expire-seconds | 120 | 图形验证码有效期（秒）【推测】 |
| security.sms.resend-interval-seconds | 60 | 重发倒计时（秒），即 FR-203 倒计时时长 |
| security.sms.daily-limit | 100 | 单手机号每日发送上限，即 FR-204 上限值 |
| security.sms.max-verify-attempts | 5 | 短信验证码最大校验尝试次数，即 FR-206 超限阈值 |
| security.sms.aliyun.* | 保密配置 | 阿里云短信通道（app-key/app-secret/sign-name/template-code=SMS_512135018） |

**异常路径**：
1. 图形验证码错误/过期/重复使用 → 拒绝发短信（FR-201）。
2. 倒计时未结束重复请求 → 拒绝发送（FR-203）。
3. 达到每日上限 → 拒绝发送（FR-204）。
4. 验证码错误/过期/超尝试次数 → 校验失败（FR-206）；超限后的账号处置素材未定义（问题清单第 9 题）。
5. 阿里云发送失败的用户侧行为素材未定义（问题清单第 13 题）。

### 5.3 密码过期强制修改

**为什么存在**：服务 U1 的场景 2。长期不改密的账号泄露后长期有效，本章定义「过期不阻断登录、但阻断业务」的强改密闭环。

**叙述**：密码超过配置周期未修改的账号仍能登录，系统在登录成功时返回过期标记，前端据此弹改密窗并锁死后续操作；改密需旧密码、满足复杂度的新密码与短信验证码三要素；存量老账号（无 pwdUpdateTime）不立即过期。

**密码生命周期状态链**：

```
正常 --超过配置周期未修改--> 过期 --登录成功且未改密--> 强制改密中 --改密成功--> 正常
存量账号(pwdUpdateTime为空) --不进入过期（起算规则见问题清单第 7 题）
```

**行为级规则**：

- **FR-301** 密码超过配置周期未修改时，账号仍可正常登录，登录成功后系统返回密码过期标记。
- **FR-302** 前端根据密码过期标记强制显示修改密码弹窗；未完成密码修改前，用户不能进行后续操作。
- **FR-303** 修改密码需要填写旧密码、新密码及短信验证码。
- **FR-304** 强制改密场景发送短信不需要图形验证码，但仍受倒计时限制。
- **FR-305** pwdUpdateTime 为空的存量账号不会立即过期。
- **FR-306** 新密码必须同时包含数字、大写字母、小写字母与复杂符号，不符合复杂度要求时不能提交。

**密码过期参数（Apollo）**：security.password.expiry.enabled=true（策略开关）、security.password.expire-days=90（过期天数，即 FR-301「配置周期」的值）。周期起算点与「复杂符号」字符集素材未定义（问题清单第 3、6、7 题）。

**异常路径**：
1. 旧密码错误 → 改密失败（素材未细述提示行为）。
2. 新密码复杂度不满足 → 不能提交（FR-306）。
3. 改密短信验证码错误/超限 → 校验失败（同 5.2 FR-206）。
4. 强制改密弹窗能否被关闭或以退出登录绕过 → 素材未定义（问题清单第 14 题）。

### 5.4 用户手机号维护

**为什么存在**：服务 U2 的场景 4。短信验证码的可达性依赖账号手机号的准确性，本章补齐手机号的维护入口与生效链路。

**叙述**：管理员在用户管理页面修改并保存用户手机号，系统同步账号表，后续登录与改密短信即发往新号；手机号在页面与日志中始终脱敏。

**行为级规则**：

- **FR-401** 用户管理页面支持修改并保存用户手机号。
- **FR-402** 保存手机号时同步更新账号表，后续登录及改密短信发送使用更新后的手机号。

**异常路径**：手机号格式非法、为空或与他人重复时的保存行为素材未定义（问题清单第 12 题）。

## 6 非功能需求

- **NFR-01（可维护性）** 短信验证码与密码过期策略的关键参数（开关、有效期、倒计时、每日上限、尝试次数、过期天数）通过 Apollo 配置，调整参数不需修改代码。
- **NFR-02（安全）** 阿里云短信真实密钥（app-key/app-secret）由配置管理员维护，不随代码仓库与构建产物分发。
- **NFR-03（安全·既有方式延续）** 密码仍由前端以 MD5 形式提交后端（素材明示延续既有提交形态，非本期新增安全增强）。

素材未含性能指标、可用性指标与合规约束，按「不凑模板」原则不设立相应 NFR 条目。

## 7 约束、假设与开放问题

### 7.1 外部依赖
