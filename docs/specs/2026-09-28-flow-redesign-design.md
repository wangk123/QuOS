# 整理流程重构（flow redesign）· 设计 spec

> 日期：2026-09-28 ｜ 状态：设计定稿，待实现 ｜ 前置：reqspec-design（docs/specs/2026-09-23-reqspec-design.md）§9 偏差清单 ｜ 基线：main 7f54bcb + 在途未提交改动（断言 confirm/ask 闭环、证据删除、docx 解析）

## 1. 问题：现有六步流程的三类缺陷

### 1.1 命名：实现术语泄漏，与视图内容脱节

| 旧名 | 实际职责 | 缺陷 |
|---|---|---|
| ① 提事实 | 提取断言 + 核验 | 「事实」「断言」均非用户词；用户心智中这些句子就是「功能点规则」 |
| ② 挑矛盾 | AI 检测冲突 + 人工裁决 | 「挑」暗示人找，实际 AI 找人裁 |
| ③ 找空白 | 按维度扫**卡片摘要** | 「空白」抽象；且位置错误（见 1.2） |
| ④ 成卡片 | 组装最终产物 | 「卡片」是内部数据结构名（`Card`/`cards/`），实现泄漏 |
| ⑤ 问人 | 澄清问题汇总回收 | 是池子不是步骤（①②④都向它投递） |
| ⑥ 存档 | git 基线 | 单独成步偏薄 |

### 1.2 顺序：与代码依赖矛盾（两处）

1. **问人在成卡片之后，但它是成卡片的闸门前置**：assemble 硬闸门要求全部断言核验（tasks.py `AssembleBlocked`），推测类断言只有澄清答案回收后才自动核过（router.py resolve_clarification 联动）。按 UI 顺序走到④必被 409 拦，被迫跳⑤再折回④。
2. **找空白在成卡片之前，但它的输入是卡片摘要**：rescan_gaps 吃 `cards.load_all()`。首次整理时③扫的是「暂无卡片」，无产出；只能④之后再回头重扫③。

### 1.3 结构：步骤与池混淆、规则平铺

- 问人是待办池，包装成线性步骤导致「看不出存在必要」。
- 断言（规则）无差别平铺一张表，不挂功能树节点、无重要度——多节点整理互相污染（M1.x 偏差 #4），也无法按模块浏览。

## 2. 设计总览

```
顶栏池（全程常达）：证据池 · 澄清池（角标=未答数） · 基线
侧栏：功能树（节点带 P0/P1/P2 徽章）

门槛：功能树为空 → 拦截引导搭骨架（手工 / AI 从证据池生成→人工调整）

① 规则提取 → ② 冲突裁决 → ③ 生成画像 → ④ 查漏补缺 → ⑤ 定稿存档
```

五个步骤均为四字名，动宾结构，动词表达**人要做的判断**：

| 步骤 | 使命（兼页面副标题） | 旧对应 |
|---|---|---|
| ① 规则提取 | AI 读材料提取行为规则，逐条核验；按 模块›功能点 分组、组内按重要度排序 | ①提事实 |
| ② 冲突裁决 | 互斥规则对三选一：信A / 信B / 转澄清 | ②挑矛盾 |
| ③ 生成画像 | 当前功能点核验通过的规则，组装画像草稿 | ④成卡片（前移） |
| ④ 查漏补缺 | 按维度清单审画像「没说什么」，转澄清或判读 | ③找空白（后移） |
| ⑤ 定稿存档 | 补充意见重生成终稿，存入 git 基线 | ⑤问人+⑥存档（问人降池，存档并入） |

**术语统一**：UI 文案层「断言」→「规则」。①提取的原子句 = 规则（带出处+置信度）；③画像内 R# = 规则在功能点内的编号——两层概念贯通为一条线。数据层 `Assertion` 模型与存储不改名。

顺序修正后依赖链成立：规则核验全过（澄清回收点1）→ 画像草稿 → 缺口处置（澄清回收点2）→ 终稿存档。

## 3. 门槛：功能树骨架

规则要挂节点，节点来自功能树；但完整功能树在材料读完前不可能存在（死循环）。解法：**先有骨架，流程中长肉**。

| 项 | 设计 |
|---|---|
| 触发 | 进入①时树为空 → 空态拦截：「功能树还没有骨架——手工搭建 / AI 从证据池生成」 |
| AI 生成 | 新任务 `outline`：读证据池全部文本 → 输出 模块›功能点 多级层级。**仅树空时提供**（防覆盖已有树）；证据池为空时按钮置灰 |
| 人工调整 | AI 结果直接落到侧栏树（侧栏本有增删改），用户调整后即采纳——生成必经人工过目，闸门内建 |
| 长枝闭环 | ①提取时 AI 给规则标注归属；挂不上 → 「未归类」桶（树缺枝的探伤器）→ 现场侧栏补节点 → 行内挂载 |
| 重要度 | `TreeNode.priority`：P0/P1/P2/空（默认同级）。骨架阶段人工在树上标记；AI 初判延后 |

## 4. 逐步设计

### ① 规则提取（原 Fact.vue 重构）

- **提取**：入口不变（「提取池中相关材料」），prompt 新增树上下文（节点全路径清单），AI 逐条输出 `node` 归属。服务端校验 node ∈ 树路径集合，失配置空（防 AI 编造节点）。
- **分组展示**：按规则 `node` 全路径分组，两级折叠 UI——组 = 父路径（模块，如「支付」「支付/跨境」），项 = 功能点，组内规则平铺。顶层功能点（无父路径）归入「（未分组）」组置顶。同级功能点按 priority 排序（P0→P1→P2→空按树序），组头显示核验进度（n/m ✓）。
- **未归类桶**：置底常显，行内「归属」下拉选节点挂载（不做拖拽）；先补枝再回来挂。
- **核验交互**：全量/单点/人工过/转澄清，全部不变，行级照旧。
- **排序约束**：priority 排序仅作用于本视图分组展示，**不改变树的存储顺序**——数字路径（`0,1,2`）是节点寻址方式，重排会断引用。

### ② 冲突裁决

逻辑不变（rescan → 左右对照三选一），仅术语与文案跟随（断言→规则、问人→澄清池）。

### ③ 生成画像（原成卡片前移）

- **输入修复**：assemble 只吃 `node` 匹配当前功能点的规则（原全局规则池——修偏差 #4 的 R# 污染）。未归类规则不参与组装。
- 闸门不变：存在未核验/待实证规则 → 409 + 明细。
- 卡片按节点存储/读取不变；`/doc` 导出不变。

### ④ 查漏补缺（原找空白后移）

- **输入修复**：rescan_gaps 从全部卡片摘要改为**当前节点卡片**摘要（原吃全局卡片——与 #4 同根的 bug）。当前节点无卡片 → 空态引导先生成画像。
- 处置不变：转澄清 / 判读为设计如此。

### ⑤ 定稿存档（问人降池 + 存档合并）

页面 = 待确认项汇总（澄清池 open 项）+ 补充意见输入 + 「重新生成终稿」+ 「存入基线」。存档闸门：存在未决澄清项时提示、显式保留风险后可继续（不硬拦，风险显式化）。

### 顶栏：澄清池（原⑤问人）

- Ask.vue 改造为顶栏常驻入口 + 抽屉，角标 = open 问题数；任何步骤可开、可回收。
- 投递来源三处不变：①无依据规则转澄清、②冲突三选一转澄清、④缺口转澄清。
- 回收联动不变：answer/verify，ref 指向规则时自动核过。

## 5. 数据模型与 AI 任务变更

```python
Assertion.node: str = ""        # 功能点全路径；''=未归类
TreeNode.priority: str = ""     # ''|'P0'|'P1'|'P2'；仅展示排序用，不动树序
```

| AI 任务 | 变更 |
|---|---|
| extract（改名规则提取沿用） | 输入加树路径清单；输出断言含 node；服务端校验失配置空 |
| outline（新增） | 输入证据池文本，输出层级清单 → 落树 → 人工调整 |
| gap | 输入改为当前节点卡片摘要 |
| assemble | 输入过滤为当前节点规则 |
| conflict / verify / clarify-gen | 不变 |

历史数据兼容：存量断言 node 为空 → 全部落「未归类」桶，人工挂载或重提；不写迁移。

## 6. 错误与边界

| 场景 | 处理 |
|---|---|
| 树空时点提取 | 空态拦截引导搭骨架（未建树也可提取，全部未归类——但不引导此路径） |
| AI 归属标错 | 行内归属下拉随时改；分组是视图层，改字段即生效 |
| AI 编造节点路径 | 服务端白名单校验，失配置空进未归类 |
| outline 覆盖已有树 | 仅树空提供入口，非空隐藏 |
| 存量断言无 node | 未归类桶承接，不迁移 |
| 澄清池无人答 | ⑤定稿时显式提示保留，不硬拦（沿用原设计） |
| 重组件挂载后规则视图 | 分组渲染纯前端聚合，无服务端状态 |
