# 需求工作台重构（workbench redesign）· 设计 spec

> 日期：2026-10-01 ｜ 状态：设计定稿，待实现 ｜ 前置：flow-redesign（docs/specs/2026-09-28-flow-redesign-design.md，其视图层被本设计取代）｜ 基线：main 28db8a0 ｜ 效果图：reports/profile-overview-preview/workbench.html（v5，交互原型即行为基准）

## 1. 问题：三个层面

| 层面 | 现状 | 痛点 |
|---|---|---|
| 需求理解 | 画像只有叶节点粒度，树是纯目录 | 接到需求只能一块块读，整体理解（Why/How）缺失——根源是**生产顺序**：现有流程自底向上（叶子规则→事后聚合），整体只能是派生物 |
| 交互范式 | 五步导航（①规则提取→⑤定稿存档），每步一个页面 | 步骤导向把人限制死：闸门仪式（采纳/确认/409 拦截）、一次性展示、不能随时做任何操作 |
| 变更处理 | 补材料后手动逐材料提取；材料级代答（P1）孤立在澄清池 | 无影响分析：不知道新材料影响哪些内容，只能全量重跑或不动 |

用户定位（已确认）：**为测试工程师服务**，产物=「我的理解基线」；AI 展开+核验链=差异化灵魂，不做第二个 ChatPRD。

## 2. 设计总览

```
范式：从「步骤导向」到「文档生长」

用户唯二主动动作：① 导入材料（拖拽/⌘V/粘贴/git） ② 点「生成需求」
其余全部后台自动：大纲先出 → 细节逐节点流式完善 → 完成一块展示一块
树 = 需求文档本体（根/模块/叶三层语义），随时自由编辑，无采纳闸门
人工判断退为数据层操作：核验 / 冲突裁决 / 转待确认 —— 节点详情里行内完成
证据池 · 待确认 · 版本 = 顶栏按钮 + 弹窗
变更通用引擎：材料变更 → AI 影响分析 → 方案确认（局部/仅重扫/全量）→ 增量执行 → AI 代答采纳
```

界面两态：**落地态**（空项目=一个大导入框；有材料=列表+生成按钮）与**工作台态**（左大纲树 58% + 右节点详情 42%）。无任何步骤条/阶段/流程名词。

原型 v5 已验证的行为清单（spec 的验收基准）：

| # | 行为 | 原型演示 |
|---|---|---|
| B1 | 空态大导入框 → 材料列表 → 「✦ 生成需求」 | ①② |
| B2 | 生成后材料收进顶栏证据池按钮，可弹窗补充/删除 | ③ + 证据池弹窗 |
| B3 | 大纲树立即出现；后台逐节点完善（进度条+取消；节点三态：排队/处理中骨架屏/就绪） | ③ 自动播放 |
| B4 | 树即文档：hover ✎＋ 行内编辑节点名/描述/结构 | ③④ |
| B5 | 详情三 tab：概要/条目/存疑；行内核验（徽章联动）、冲突 A/B 三选一、转待确认（行内表单）、缺口处置 | ④ |
| B6 | 待确认弹窗：分段（等待/已答复）、记答复（口头/材料佐证）、答复→关联条目自动核过+冲突解除 | ④ |
| B7 | 版本弹窗：时间线+变更摘要+存版+导出预览 | ④ |
| B8 | 补材料 → 影响分析卡（三方案+AI 推荐+范围明细）→ 确认执行 → 局部重生成（树上仅受影响节点动） | ⑤ |
| B9 | AI 代答卡（引用新材料原文+出处）→ 采纳/忽略 → 问题关闭+条目核过+冲突解除 | ⑤ |

## 3. 界面设计

### 3.1 落地态（Landing）

- 空项目：整页一个大导入框（拖拽/点击/⌘V，支持批量），下方一行支持类型说明。
- 有材料：导入框缩为追加条 + 材料列表（名称/类型/可信度星级）+「✦ 生成需求」主按钮。
- 0 材料点生成：按钮置灰。

### 3.2 工作台布局

```
[顶栏 50px] QuOS · 项目名(v#) · … · 版本 · 证据池(n) · 待确认(n)
[后台进度条] （仅生成/重生成时）spinner+文案+进度+取消 —— 高约 34px
[主体] 左：大纲树（58%，根卡片→模块卡→叶行，独立滚动）
       右：节点详情（42%，sticky，独立滚动）
```

### 3.3 大纲树（三层语义）

| 层级 | 内容 | 来源 |
|---|---|---|
| 根卡片 | 需求一句话（这是什么）、给谁/边界、全局统计（条目数/待判断数） | understand 生成，summary 任务重生成 |
| 模块卡 | 名称+职责一句话+徽章（条目数/待判断） | 同上 |
| 叶行 | 名称+一句话+徽章（条目数/待判断/⚠冲突/画像✓） | 同上，细节随后台流水线增长 |

- **一句话=该节点画像的 goal 首句**（见 §4 数据模型），树上编辑一句话即编辑 goal——不新增树字段。
- 折叠展开；hover 出现 ✎（改名/编辑描述）＋（加子节点）；点击换右侧详情。
- 徽章=工作清单：待判断数（未核条目+未决冲突）琥珀、冲突红⚠、画像就绪绿✓。
- 根卡片角落「↻ 摘要」：手动触发上层摘要重生成（默认随存档自动）。

### 3.4 节点详情

- 面包屑（可点回上级）+ P0 徽章 + 状态徽章。
- **三 tab**（节点就绪后出现）：
  - **概要**：goal/入口/主流程/状态机/异常/依赖（现有 Profile 字段直出）；「待你判断」汇总卡（N 条未核+M 组冲突，按钮跳对应 tab）。
  - **条目**：核验进度条 + 规则行（ID/要求/出处溯源 hover/置信度徽章）+ 行内动作：**核验**（单条）、**待确认？**（行内展开表单→投递待确认池）、**✦ AI 辅助核验**（批量，只核文档级，推测级留人工）。
  - **存疑**：冲突卡（A/B 材料对照+星级，三选一：信A/信B/转待确认）+ 缺口卡（转待确认/判读为设计如此）。
- **节点三态**：排队（说明文案）→ 处理中（骨架屏+当前动作文案）→ 就绪（三 tab）。

### 3.5 三弹窗 + 影响分析弹窗

| 弹窗 | 结构 | 关键交互 |
|---|---|---|
| 证据池 | 追加材料区 + 列表（类型/星级/已并入状态/删除） | 删除联动角标；「↻ 重新生成」→ **先出影响分析**（不直接跑） |
| 待确认 | 分段 tab 等待(n)/已答复(n)；问题卡（来源标签：哪条规则/哪组矛盾引发） | 记下答复（卡内表单：内容+口头/材料佐证）→ 提交后关联条目自动核过、冲突自动解除；忽略；**AI 代答卡**置顶（见 §3.7） |
| 版本 | 时间线（当前绿点）+ 变更摘要 chips | 存为版本（顶栏项目名旁出 v#）；预览/导出需求文档（.md） |
| 影响分析 | 新材料条 + 关联清单（节点/冲突/待确认/条目）+ 三方案卡（radio） | 方案见 §3.6；「按所选方案执行」 |

### 3.6 变更影响分析（通用引擎）

任何材料入口（证据池补料 / 待确认处理时的材料佐证）统一走：

```
材料入池 → POST /regen/impact（AI 关联分析）
  → 方案卡：局部重生成（AI 推荐：受影响节点清单+「已有人工判断保留」）
            仅重扫待确认（树不动，只跑 AI 代答）
            全量重新生成（人工强制；明示「人工修改会被重新组织，不保证保留」）
  → 人工确认 → 对应 job 执行（进度条/取消同 B3）
  → 局部：树上仅受影响节点进入处理中；rescan：直接出代答卡
```

### 3.7 AI 代答卡（复用已上线 P1）

重扫后，待确认弹窗置顶蓝条「AI 从新材料找到 n 个可能答案」；每卡：出处（材料名+章节）+ 引用原文 + [采纳][忽略] + 采纳后联动说明。**采纳 → 问题关闭 + 关联条目核过（置信度升级）+ 关联冲突解除 + 角标-1**。即现有 clar-review / resolve_clarification 的 UI 前移，逻辑不变。

## 4. 数据模型

| 项 | 变更 |
|---|---|
| `Profile` | 加 `kind: str = "leaf"`（leaf\|module\|root）。根画像存 `profiles/__root__.md`（node="__root__"），复用现有字段：goal=需求一句话、entry=给谁/边界、flow=端到端主线、boundaries=风险、note=全局约束。模块画像 node=模块全路径，goal=职责、boundaries=边界。**无新存储格式** |
| 树一句话 | = 节点画像 goal 首句，渲染时从 `_latest_profiles` 取；tree.md 不改 |
| `Rule` / `Clarification` / `Evidence` / 基线 git | **不变**（Evidence 加前端态「已并入/新」，不入库） |
| 待同步 | 上层画像与叶子实况的偏差（新条目挂树后根/模块摘要滞后）以徽章提示，重生成时机=手动 ↻ 或随存档；不自动（防闪变） |

## 5. AI 任务

| 任务 | 变更 |
|---|---|
| understand（原 outline 升级） | 输入证据池全部材料（含图片）；输出：根画像草稿 + 树骨架（模块+叶）+ 每节点 goal 一句话。全部 conf=推测、verified=false |
| extract / verify / conflict / gap / clar-review | 不变，改由流水线自动串调 |
| assemble | 输入加父节点 goal（上下文）；**AssembleBlocked 从异常改跳过**：未核条目的节点不组装、记入 job.blocked，流水线继续——闸门数据化 |
| summary（新） | 输入=子节点画像聚合；输出=根/模块画像重生成（只在 ↻ / 存档 / 局部重生成完成时调用） |
| impact（前移启用） | 输入=新材料提取结果+现有规则/待确认清单；输出=受影响节点/条目/冲突/待确认+方案建议（partial\|rescan\|full） |

## 6. 后台流水线（generate job）

```
generate = outline(understand) → 逐材料 extract+verify（复用 _run_extract_verify）
         → conflict rescan → 逐叶 assemble（blocked 跳过）→ gap rescan → summary
进度=阶段+节点计数；取消=保留已完成（cancelled 态）；前端轮询 GET /jobs（沿用）
```

- jobs 机制升级：状态落盘 `jobs.json`（id/kind/phase/cur/total/status/完成节点清单），服务重启 resume（现状内存态、重启即丢）。
- 生成中的树编辑：允许编辑**已完成/排队**节点（编辑过的节点若在队列中则重跑该节点）；**处理中**节点编辑置 pending，该节点完成后立即重跑一次。
- 局部重生成 job：只含受影响节点的 assemble/summary + 关联待确认重扫。

| 端点 | 说明 |

## 9. 错误与边界

| 场景 | 处理 |
|---|---|
| 生成中刷新/重启 | jobs 落盘 resume；前端恢复进度条 |
| 生成中点取消 | cancelled：已完成节点保留、处理中作废、排队不动 |
| AI 代答质量 | 引用原文+出处，采纳权在人（P1 原则不变）；忽略不消失进已忽略段 |
| 全量重生成 vs 人工判断 | 方案卡明示不保证保留；建议永远默认局部 |
| 材料删除后重生成 | 删除材料的条目随下次重生成移除（提示确认） |
| 材料过大致 job 长 | 逐材料/逐节点推进可见进度；取消随时可点 |
| understand 失败 | 空树+错误条重试；不阻塞手工搭树 |
| 存量项目 | 数据全兼容；首次打开=树+已有画像直接进工作台（无 landing）；「重新生成」可用 |

## 10. 实施分批

| 批 | 内容 | 依赖 |

| A 流水线地基 | understand 任务、generate job 串调、AssembleBlocked→跳过、jobs 落盘+cancel | 无 |
| B 工作台前端 | Landing、Workbench 壳、WbTree（三层语义+徽章+编辑）、WbDetail（三态+三 tab，先读后写） | A |
| C 人工判断闭环 | 条目核验/冲突/转待确认/缺口 行内交互（回接既有 API）+徽章联动 | B |
| D 三弹窗 | 证据池/待确认（记答复+联动）/版本（存版+导出预览） | B |

| F 收尾 | /doc 分层导出、旧五步视图与导航删除、存量数据走查 | 全部 |

## 11. 对既有设计的影响

- flow-redesign spec：数据层成果（规则挂节点、画像按节点、澄清池、闸门数据化）全部沿用；**视图层五步导航被本设计取代**。
- 材料级代答 P1：逻辑不变，UI 并入待确认弹窗与变更引擎。
- M2 增量定位（impact）：由本设计前移实现（材料级），M2 的 diff 级沿用同任务。
- 效果图 reports/profile-overview-preview/workbench.html 为交互行为基准；index.html/prototype.html 为过程稿（可删）。
