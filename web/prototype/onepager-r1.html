核心链路 · 它是怎么工作的
材料进入→ 解析识别→ 自动分类→ 人工确认→ 特征提取→ 结构化抽取→ 人工复核→ 发布固化→ API / SSE 交付
琥珀色 = 人工环节：机器负责识别与计算，人只做确认与裁决。全链无静默降级——配置缺失、依赖不可用一律显式失败。
主线 · 从材料到交付

材料进入与解析

业务起点正文 ↗

一切从受理单开始——全部业务动作挂在它上面，影像树定义这笔业务要哪些影像、怎么算齐。任何渠道进来的任何文件——PDF、扫描件、Office、压缩包、音视频——都被转成同一种可分类、可抽取的标准内容；解析失败显式可见、可人工修复。

材料分类

定类正文 ↗

机器双路径给候选（冷启动评分 + 确认样本匹配），人做终审；确认过的样本反哺匹配，越用越准。机器拿不准的一律转人，不猜。

结构化抽取与发布

核心产出正文 ↗

把「材料里的那张表」变成带证据、可校验、可发布的数据。字段校验与数据勾稽两道门拦在发布前；发布即固化，此后不可再改。

对外交付

交付面正文 ↗

固定路径、POST 查询、幂等写、SSE 通知——外部系统可以放心依赖的契约面。查空与分类不存在严格区分，单个影像出问题不影响其余返回。

支撑 · 质量与运转

影像合规审查

质量闸正文 ↗

按影像树规则自动重判影像合格性——分类确认、数据修正等事实一变就自动补算，页面上没有「开始审查」按钮。当前是轻量版，完整审查引擎是目标态。

特征提取与媒体

媒体面正文 ↗

音视频、图片先转成与 OCR 等价的标准数据，再进统一抽取。特征只记事实、值、置信度与证据，不产「通过与风险」的业务结论。

智能分类助手

调优面正文 ↗

分类准确率的调优面——Agent 负责取证与起草，系统强制验证（真实试算 + 回归），人终审；Agent 自报完成无效。

规则管理

校验配置正文 ↗

勾稽与校验规则的配置面——规则在这里设计、发布，发布门前由规则引擎执行。业务结论不等于接口报错。

配置与实时通知

运转底座正文 ↗

一切配置集中管理、运行期冻结快照——保存不等于可运行，缺关联显式停止。页面感知走「事务内发件箱 → SSE 推送」，前端只重读权威资源、不消费事件数据。
